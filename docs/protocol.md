# 정음 메모패드 통신 형식

MemoPad 가 정음 메모패드(9.5.1.133)와 주고받는 형식입니다. 정음 메모패드끼리 주고받는 바이트를 기록하고, 바이트를 바꿔 보내며 확인했습니다.
코드: `MemoPad\Net\JuProtocol.cs` (메모 머리 · 회람 칸), `MemoService.cs` (메모 포트), `ChatProtocol.cs` · `Ui\ChatService.cs` (대화).
확인: `MemoPad.Checks` (이 PC 안에서), `MemoPad.Checks --jungum <IP> <ID>` · `--jungum-wait` · `--jungum-chat` (실제 정음 메모패드와).

- 숫자는 모두 4바이트 little-endian.
- **ANSI** = CP949. **이중 글자 칸** = ANSI 글자 + NUL + 같은 글자의 UTF-16 + NUL (칸 크기 안에서).
- 연결 하나에 일 하나 (보내고 끊음). 응답이 없는 명령도 있습니다.

## 포트

| 포트 | 쓰임 |
|---|---|
| 9710 | 메모 · 회람 · 상태 확인 · 회람 알림 |
| 9712 | 대화창 |
| 받는 쪽이 알려 줌 (보통 9726) | 첨부 파일 |

## 메모 보내기 (9710)

| 방향 | 내용 |
|---|---|
| → | `01` |
| ← | `02` 받음, 또는 `03` + [바이트 수] + UTF-16 부재중 문구 (그리고 끊음) |
| → | `04` + 메모 머리 520바이트 + 회람 칸 642바이트 × 칸 수 |
| ← | `09` + `23` + 35바이트 (`23` + UTF-16 버전 "9.5.1.133" + 0) + `0` + `1F` |
| → | `05` + [본문 바이트 수 n] + [n] + 본문 (RTF, CP949, 끝에 NUL 포함) |
| ← | `20` |
| → | `06` + `0` |
| ← | `63` 끝, 또는 첨부가 있으면 `43` + [첨부 포트] |

## 메모 머리 (명령 `04` 뒤 520바이트, 자리는 그 안에서)

| 자리 | 크기 | 내용 |
|---|---|---|
| 0 | 128 | 보낸 사람 IP (ANSI + NUL). **NUL 바로 뒤에 `00 10 00 00 F0` + 첨부 수(2바이트)**: IP 길이에 따라 자리가 움직임. 받는 쪽은 NUL+2 가 `10` 일 때만 NUL+6 의 첨부 수를 읽음 |
| 128 | 64 | 보낸 사람 ID (이중 글자 칸) |
| 192 | 64 | 보낸 사람 이름 (이중 글자 칸) |
| 322 | 64 | 버전 UTF-16 ("9.5.1.133") |
| 448 | 4 | 종류: `0` 메모, `2` 회람 (시작한 사람 → 첫 사람), `3` 회람 (넘김 · 결과) |
| 452 | 16 | 메모 id (GUID). 회람은 회람 내내 같은 값 |
| 468 | 4 | 0 |
| 472 | 16 | 창 X · Y · 너비 · 높이 (화소) |
| 488 | 4 | 바탕색 번호 (0~17, `MemoColors.Jungum`) |
| 492 | 8 | 만든 시각 (OLE 날짜, double: 1899-12-30 부터의 날 수) |
| 500 | 8 | 고친 시각 (OLE 날짜) |
| 508 | 4 | 0 |
| 512 | 4 | 1 |
| 516 | 4 | 회람 칸 수 |

회람 칸 (642바이트): [상태 2] [IP 256] [ID 128] [이름 128] [E-Mail 128], 글자는 UTF-16. 상태의 아래 바이트 `3` = 전달함, `0` = 아직 (위 바이트는 정음 메모패드가 남기는 쓰레기 값).

## 첨부 (받는 쪽이 알려 준 포트)

| 방향 | 내용 |
|---|---|
| → | `50` `10` `10` `37` + [총 바이트 위 4] + [총 바이트 아래 4] |
| ← | `51` |
| 파일마다 → | `52` + [이름 바이트 수] + UTF-16 파일 이름 + NUL |
| 조각마다 → | [조각 바이트 수] + 조각 (2048바이트 이하) |
| ← | `53` |
| → | `54` (다음 조각) … 파일 끝은 [`0`] |
| ← | `51` (다음 파일) |
| 끝 → | `52` + `0` + `44` |

## 상태 확인 (9710)

`32` → `34` 있음 / `33` 부재중. 연결이 안 되면 꺼져 있음.

## 회람

차례로 돕니다. 메모 머리의 보낸 사람(IP · ID · 이름)은 **늘 회람을 시작한 사람**입니다.

1. 시작한 사람 → 첫 사람: 종류 `2`, 회람 칸 전체 (상태 0).
2. 받은 사람 → 시작한 사람: 받음 알림 `16`.
3. 받은 사람은 회람 칸에서 자기 자리를 IP · ID 로 찾습니다. 정음 메모패드는 **ID 로 찾으므로** 회람 칸에 ID 가 있어야 합니다 (주소록에 ID 를 넣어 두세요).
4. [회람 전달]: 시작한 사람에게 전달 알림 `17`, 다음 사람에게 종류 `3` (자기 칸 상태 = 3).
5. 마지막 사람은 시작한 사람에게 종류 `3` (모든 칸 = 3). 시작한 사람 쪽에서 "[회람 결과입니다.]" 메모가 됩니다.

받은 사람 쪽 정음 메모패드는 받은 내용을 `> ` 로 감싸고 맨 위에 "[이름의 의견]" 줄을 넣습니다. MemoPad 도 같게 합니다.

회람 알림 (9710, 응답 없음): `16` 받음 / `17` 전달 + [`10`] + 메모 id 16바이트 + [바이트 수] + ANSI IP + NUL.

## 대화창 (9712)

메시지 = [명령] + [내용 바이트 수] + 내용. 글자 = [바이트 수] + UTF-16 + NUL. 들어가는 쪽(손님)이 연결하고, 연결받은 쪽(방장)이 모두에게 돌려줍니다.

| 명령 | 방향 | 내용 |
|---|---|---|
| `02` | 손님 → 방장 | (없음) 들어가기 |
| `0D` | 손님 → 방장 | 내 정보: [대화명] [IP] [이름] [E-Mail] `0` `0` |
| `66` | 방장 → 손님 | 알림 글 (">>> ○○과 연결이 되었습니다.", "입실", "퇴실") |
| `16` | 방장 → 손님 | 참여자: [얼굴 번호] [대화명] [IP] [이름] [E-Mail] `0` |
| `65` | 손님 → 방장 | 말: ["대화명: 할 말"] |
| `69` | 방장 → 모두 | 말 돌려주기: [말한 사람 IP] ["대화명: 할 말"] |
| `67` | 손님 → 방장 | 나가기 |

## 그림

정음 메모패드의 그림 메모는 보낼 수 없습니다 (메뉴에 보내기가 없음). MemoPad 의 그림 메모는 PNG 한 장짜리 RTF(`\pngblip`)로 보내고, 정음 메모패드에서 그대로 보입니다.

## 정음 메모 파일 (*.HMD)

정음 메모패드의 메모 폴더(설치 폴더의 `Desktop`, 권한이 없으면 `%LOCALAPPDATA%\VirtualStore\...`)에 메모마다 하나. 메모 관리기 → ⋯ → 정음 메모 가져오기가 읽습니다.

| 자리 | 내용 |
|---|---|
| 0 | "SAMSUNGMEMO_1.2" + `1A` |
| 0x11 | 종류 (1 받은 메모, 3 회람 결과) |
| 0x15 | 메모 id |
| 0x29 · 0x2D · 0x31 · 0x35 | X · Y · 너비 · 높이 |
| 0x39 | 바탕색 번호 |
| 0x41 · 0x49 | 고친 · 만든 시각 (OLE 날짜) |
| 0x61 · 0x161 · 0x1E1 | 보낸 사람 IP · ID · 이름 (UTF-16) |
| `{\rtf` 부터 NUL 까지 | 본문 |
